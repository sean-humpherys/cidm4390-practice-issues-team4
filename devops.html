What are the responsibilities of a DevOps professional?

What the DevOps person does on a Scrum team

Scrum doesn't define a "DevOps person." The framework has three roles: Product Owner, Scrum Master, and Developers. In practice, many teams include someone with a DevOps focus among the Developers, and what they do depends on the team.

The core idea

A DevOps-minded team member bridges building software and running it. Their goal is to help the team deliver working, tested, deployable increments every sprint, and to keep that software healthy once it's live. Scrum expects a potentially releasable increment at the end of each sprint, so someone has to make the path from code to production smooth and automated.

Typical responsibilities

CI/CD pipelines

Build and maintain the automation that compiles, tests, and deploys code whenever developers merge changes (GitHub Actions, GitLab CI, Jenkins, Azure DevOps).

Infrastructure as code

Define servers, networks, and cloud resources in version-controlled files (Terraform, CloudFormation, Pulumi) so environments are reproducible rather than hand-built.

Environments

Provide dev, test, staging, and production environments, and keep them consistent with each other.

Containers and orchestration

Package apps with Docker and run them with Kubernetes or a similar platform.

Monitoring and observability

Set up logging, metrics, dashboards, and alerts (Prometheus, Grafana, Datadog) so the team knows how the system behaves in production.

Release management

Enable safe releases through blue/green deployments, feature flags, and fast rollbacks.

Security and compliance

Build security scanning, secrets management, and access controls into the pipeline (often called DevSecOps).

Incident response

Help troubleshoot production issues and run post-incident reviews.
